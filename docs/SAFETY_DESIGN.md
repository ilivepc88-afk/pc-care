# 安全设计

## 核心原则

PcCare 将“体检”“确认”“执行”分开。扫描阶段只读；执行阶段不接受用户输入的文件路径，而是接收固定清理分类 ID，使用内置规则重新扫描后再删除。

## 权限边界

- 主界面默认以普通用户启动。
- 只读体检不申请管理员权限。
- 点击执行清理后，程序通过 Windows UAC 启动同一个 EXE 的提权模式。
- 普通进程只传递任务 GUID 和分类 ID，例如 `windows-temp`，不传递文件路径或命令。
- 提权进程重新加载编译进程序的白名单，并拒绝未知分类。
- 提权进程不显示主界面、不提供命令行或脚本入口，完成后只写入本地结果文件。

## 文件系统防护

对每一个扫描和删除目标：

1. 使用 `Path.GetFullPath`规范化路径。
2. 以带目录分隔符的规范化根路径比较，避免 `Temp` 与 `Temp-other` 前缀混淆。
3. 拒绝根目录、子目录和文件上的重解析点。
4. 不跟随符号链接和目录联接点。
5. 扫描时只接受超过 7 天且可独占打开的文件。
6. 删除前提权进程重新扫描，再次检查路径和重解析点。
7. 逐文件删除；失败时记录并继续，不强制结束占用进程。
8. 不删除白名单根目录，不递归删除目录树，不删除空目录。

## 固定禁止项

- 用户桌面、文档、下载、收藏夹、浏览器数据、网盘目录。
- 注册表清理和所谓无效注册表项。
- Prefetch、事件日志、Windows 更新数据库。
- Windows 服务、驱动、计划任务修改。
- Windows Update、Defender、安全策略、遥测、搜索索引修改。
- 内存“释放”、TCP参数、HPET、电源和游戏优化。
- 在线脚本、插件、规则更新、远程接口和遥测。

## 数据与隐私

- 不联网，不上传任何信息。
- HTML报告没有CDN、在线字体、脚本或远程图片。
- 报告默认写入程序旁的`Reports`目录；目录不可写时使用当前用户文档目录。
- 管理员清理结果通过当前用户本地应用数据目录交换，任务名由随机GUID生成。

## 视觉效果优化边界

- 只修改当前用户（HKCU）的视觉效果，不申请管理员权限。
- 使用Windows `SystemParametersInfo`接口关闭动画、淡入淡出、阴影和平滑滚动，并显式保持字体平滑开启。
- 只写入固定的Explorer/DWM视觉效果值，不接受任意注册表路径或参数。
- 第一次应用前将原设置保存至`%LOCALAPPDATA%\PcCare\Backups\visual-effects.json`；重复应用不覆盖原备份。
- 支持一键恢复；恢复成功后才删除备份。执行中发生错误时尝试立即回滚。
- 不结束Explorer进程，不强制注销或重启电脑。

## 当前剩余风险

文件系统操作天然存在扫描后、删除前的竞态窗口。当前实现会在提权后重扫，并在删除前再次检查路径和文件属性。后续阶段可使用 Windows 原生文件句柄和“禁止跟随重解析点”标志进一步收紧。
